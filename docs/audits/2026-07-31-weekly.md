## Findings

### A11Y-01 — "Mark done" is a 16×16 target on phone · **Critical**

The primary completion control on every lesson row measures **16×16 CSS px** at
375. WCAG 2.2 SC 2.5.8 requires 24×24 minimum; `BUILD_STANDARD`/`CLAUDE.md` §4
require **≥44px** on phone and tablet. There is no `::before` hit-area
inflation on these buttons (`getComputedStyle(el,'::before').content === "none"`),
so the project's own ≤900px coarse-pointer floor is not reaching them.

*Evidence — Observed.* True mobile emulation (375×812, DPR 3, `isMobile`,
`hasTouch`); three instances measured in-viewport at x=293, y=466/627/789, each
`16×16`. `mcp-weekly-375.png`.

*Impact.* Marking a lesson taught is the most repeated action in the product,
and on a phone it is a 16px tap next to other controls. Mis-taps on a
completion toggle silently change plan state.

*Fix.* Apply the existing 44px `::before` inflation pattern (the one
`ToggleGroup` already uses under `(pointer: coarse), (max-width: 900px)`) to the
mark-done button, keeping the 16px visual dot. Add the control to whatever probe
asserts target sizes so it cannot regress.

### A11Y-02 — Focus indicator fails 3:1 on lesson cards · **High**

The focus ring (`rgb(22,160,107)`, the accent) sits on lesson-card backgrounds
at **2.84–2.93:1 in 5 of 6 cards sampled** — below the 3:1 required by WCAG 2.2
SC 1.4.11 (Non-text Contrast) and SC 2.4.13 (Focus Appearance). Only one card
passed, marginally, at 3.02:1.

*Evidence — Observed.* Measured in-page with the card backgrounds resolved
through a canvas before the luminance maths — necessary because the backgrounds
are `oklch()` values (e.g. `oklch(0.95013 0.0087113 none)`) that naive colour
parsing mis-reads.

*Impact.* Keyboard users lose track of position across a 350-focusable-element
page. The ring is *present* everywhere (see "What is working"), just not
*visible enough* against the tinted card fills.

*Fix.* Darken the ring or add a 1px light outer companion ring so the indicator
contrasts against both the tint and the surface — a two-tone ring is the usual
answer when the backdrop varies by subject colour. Re-measure across all 8
subject tints, not just the six sampled.

### UX-01 — The primary task cannot be performed on this route in the `paper` frame · **High**

There is **no add-lesson affordance on `/weekly`** in the rendered frame: zero
matches across all 350 focusable elements, and none in the accessibility tree.
The cause is structural, not a hidden control:

- `components/week-v2/WeekA.tsx:101,289` (glass) and
  `components/week-v2/WeekC.tsx:97,252` (color) **do** implement `addLesson`.
- `components/weekly/WeekColumns.tsx` (paper — the frame this account renders)
  **has no lesson-creation path at all**.
- The only `"+ Add lesson"` button in the codebase
  (`components/weekly/weekly-board.tsx:634-648`) is documented in its own
  comment as *"non-functional; lesson creation is out of scope for this
  increment"* — and that component is **not rendered**
  (`app/(planner)/weekly/page.tsx:13`).

*Evidence — Observed* (live DOM: 350 focusable, `anyAddLesson: false`) **+**
source at the lines cited.

*Impact.* A core capability is gated by what `CLAUDE.md` calls a cosmetic axis:
"a frame changes layout/material, never the global tone." A teacher on the paper
frame cannot add a lesson from the week view and gets no explanation — the
feature is simply absent, not disabled with a reason.

*Fix.* Decide the contract and make it uniform: either port the WeekA quick-add
into WeekColumns, or state in-product that lesson creation lives on `/daily`.
Either way, delete the misleading non-functional stub in `weekly-board.tsx` so a
future reader does not restore it. This is the same class of defect the codebase
already learned once — see the note at
`components/weekly/save-target-dialog.tsx:10-28` about a control that looked
live but wrote nothing.

### A11Y-03 — Nested interactive controls on 30 lesson-card nodes · **High**

Lesson cards render a `role="button"` band (`aria-label="Expand lesson"`) that
**contains focusable descendants**. Nested interactive elements produce an
ambiguous accessibility tree: screen readers may announce only the outer
control, and the inner controls' roles are unreliable.

*Evidence — Observed.* axe `nested-interactive`, serious, **30 nodes**,
e.g. `div[data-planner-item="lesson:m-12-0"] > .weekly-lesson-card_fullContent__* > .weekly-lesson-card_band__*[role="button"]`
— "Element has focusable descendants". `.audit/screens/axe-weekly.json`.

*Fix.* Make the band a non-interactive container and move the expand action to
its own real `<button>` beside the inner controls, or keep the band interactive
and remove tabbability from the descendants. The current shape cannot be made
correct with ARIA alone.

### A11Y-04 — 13 contrast failures in grid chrome · **Medium**

axe reports 13 `color-contrast` nodes on `/weekly`:

- `.WeeklyGrid_currentTag` "This week" — **2.84:1** (`#c9871a` on `#fff8e7`,
  11px bold). Needs 4.5:1.
- `.WeekColumns_colHeadDate` day abbreviations ×11 — **2.93:1**
  (`#908fa3` on `#eef9f2`, 12px).

*Evidence — Observed*, axe, `.audit/screens/axe-weekly.json`. **Valid for
paper/wash/mint/light only.**

*Impact.* "This week" is the orientation cue for the whole view; the day
abbreviations sit in the column headers a teacher scans constantly.

*Fix.* Darken both tokens for the light tone. Note the abbreviations are
`aria-hidden="true"` with the full day name exposed via the header's
`aria-label` — correct for AT, so this is purely a visual-contrast fix.

### UX-02 — Grid/List toggle reports a state the app is not in · **Medium**

At ≤900px the route falls back to List view, but the segmented control still
reports **`Grid` with `aria-checked="true"`** while `LIST VIEW` is rendered.

*Evidence — Observed* at 768 and 375: `toggle: [{text:"Grid", checked:"true"}, {text:"List", checked:"false"}]`
with `renderedView: "list"`. `mcp-weekly-768.png`, `mcp-weekly-375.png`.

*Impact.* A screen-reader user is told Grid is selected while looking at a list;
a sighted user sees the Grid pill highlighted and may tap it repeatedly with no
effect. The fallback itself is good design (see "What is working") — the state
reporting is what is wrong.

*Fix.* Reflect the *effective* view in `aria-checked`, and either disable Grid
below 900px with a tooltip explaining why, or label the control "Grid
(desktop)".

### RSP-01 — The route's only `<h1>` is unreadable below desktop · **Medium**

`h1.view-title` "The Week" is clipped to **41px against 113px of content** at
768 (renders as "T…"), and collapses to **0px width** at 375 — no page heading
at all.

*Evidence — Observed.* 768: `{w:41, scrollW:113, clipped:true}`. 375:
`{w:0, scrollW:88, clipped:true}`. `mcp-weekly-768.png`.

*Impact.* Loses the page's primary landmark heading for both sighted users and
anyone navigating by headings.

*Fix.* Let the title wrap or shrink rather than clip; if horizontal space is
genuinely unavailable in the chrome bar, move the `h1` into the content area
(where "Week 12" already renders legibly) and keep a visually-hidden `h1` in the
bar.

### RSP-02 — Brand pill overlaps the Personal/Team toggle on phone · **Medium**

At 375 the brand element (x 24→86) and the Personal/Team control (x 57→101)
**overlap by 29×44px**. The logo is visibly obscured.

*Evidence — Observed*, geometry, plus `mcp-weekly-375.png` where the overlap is
plainly visible top-left.

*Impact.* The Personal/Team switch is the highest-consequence control in the
product (it decides whether an edit hits the whole team). Overlapping it with
another element on the smallest viewport risks mis-taps into Team mode.

*Fix.* Collapse the brand to the mark alone below ~420px, or wrap the chrome bar
so the two never share horizontal space.

### RSP-03 — Touch targets under the ≥44px contract at both sub-desktop tiers · **Medium**

| Control | Width | Measured |
|---|---|---|
| Appearance gear | 768 | **23 × 23** |
| View / Edit, Personal / Team | 768 | 42 × 34 |
| Console nav (Day…Teach) | 375 | 47–54 × **32** |
| Grid / List | 375 | 51–55 × **26** |
| Drag handle | 375 | **20 × 20** |

*Evidence — Observed*, DOM measurement at both widths (375 under true mobile
emulation).

*Impact.* The Appearance gear at 23×23 is below even WCAG 2.2's 24×24 floor. The
console nav is the app's primary navigation.

*Fix.* Extend the existing coarse-pointer `::before` inflation to the chrome bar
and console nav — the mechanism already exists and simply is not applied here.

### VIS-01 — Right-rail tab labels run together · **Medium**

"Resources", "To-do" and "Chat" render with **zero gap** — measured
`gaps: [0, 0]` — producing the visible string **"ResourcesTo-doChat"**.

*Evidence — Observed.* Bounding boxes: Resources right=1125, To-do x=1125;
To-do right=1164, Chat x=1164. Visible in `mcp-weekly-1440-paper-mint.png`.

*Impact.* Three separate controls read as one nonsense word; the boundary
between tabs is invisible until hover.

*Fix.* Add horizontal gap/padding to the tab row (the adjacent Tabs/Stack
segmented control is correctly spaced and can supply the value).

### VIS-02 — Resource grid forces horizontal scrolling inside the rail · **Low**

`ResourcesPanel_grid` is 520px wide inside a 282px container, so the tile grid
scrolls sideways and labels clip mid-word ("YOUTUB", "SLIDES").

*Evidence — Observed.* Ancestor chain: `ResourcesPanel_scroll` has
`overflow-x: auto`, `scrollWidth 520` vs `clientWidth 282`. **The content is
reachable** — I initially read this as content loss and corrected it after
inspecting the scroll container.

Note `document.scrollWidth` reports **zero** document overflow here, so a
document-level overflow probe would pass this route while tiles sit 148px
outside the viewport.

*Fix.* Let the tile grid reflow to a single column at rail widths below ~320px
rather than scrolling sideways within an already-narrow panel.

### VIS-03 — Aggressive truncation across grid cards · **Low**

At 1440 in the grid, titles and chips clip heavily: "Frac…", "Mid…",
"Re-engagement:…", "Multiplying a fraction by a…", unit chips to "Fra…" /
"Real…", and **subject names to "Read…"**.

*Evidence — Observed*, `mcp-weekly-1440-paper-mint.png`.

*Impact.* Five day-columns plus a fixed resource rail leave ~200px per column.
A truncated *subject* name is the worst case — subject is the card's primary
identifier and is already carried by colour, so the text adds nothing when
clipped to four characters.

*Fix.* Drop the redundant subject text where the colour stripe and unit chip
already identify it, and give the title the reclaimed width; allow two-line
titles before ellipsis.

### CODE-01 — Dead non-functional affordance retained in the tree · **Low** *(Inferred)*

`components/weekly/weekly-board.tsx` renders a full `"+ Add lesson"` Button with
an `aria-label`, a tooltip promising "opens the new-lesson form pre-filled with
this day", and a deliberately empty `onClick`. The file is not rendered today,
so it harms no user now — hence Inferred, not Observed.

*Risk.* If this component is ever re-mounted, it ships a control that announces
itself to assistive tech and does nothing — the precise false-success pattern
`save-target-dialog.tsx:10-28` documents as a past incident.

*Fix.* Delete the stub, or gate it behind the real creation path when UX-01 is
resolved.

## What is working well — protect these during fixes

- **The ≤900px fallback from Grid to List is a genuine responsive decision**,
  not a shrink. It re-prioritises to a day-grouped list, keeps every lesson's
  subject, unit, standards and resource count, and labels itself honestly:
  *"Same data as the grid view, listed by day."* Only its `aria-checked`
  reporting (UX-02) is wrong — keep the behaviour.
- **Tab order is clean.** 350 focusable elements and **zero positive
  `tabindex`** — no tabindex hacks anywhere. A skip-to-content link is present.
- **A focus indicator exists on every one of 60 sampled controls** (0 missing).
  The defect in A11Y-02 is contrast, not absence — do not "add focus rings",
  adjust the colour.
- **Day headers use the correct AT pattern**: `aria-label="Sunday (Sun)"` on the
  header with the visual abbreviation marked `aria-hidden="true"`. Fix the
  colour in A11Y-04 without touching this markup.
- **WeekA's quick-add is well-built** — a *synchronous* in-flight ref guard
  against double-create, an honest inline error ("Couldn't add the lesson —
  check your connection and try again") with a 6s timeout, and no fabricated
  success. This is the implementation UX-01 should be ported *from*.
- **Reduced motion is handled broadly** (213 files), including an opacity-only
  drag fallback in `lib/collapse-on-drag.ts`.
- **Build, lint, and types are all clean**, and 1342 tests pass — the route is
  not carrying hidden correctness debt.
