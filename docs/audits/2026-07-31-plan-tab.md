## B. IMPROVEMENT FINDINGS

Deliberately kept out of the §A sizing. Marked **Correction** (fixes an observed failure)
/ **Enhancement** (beyond correction) / **Experiment** (worth prototyping, not yet
justified).

### B1 · Fork state is invisible on every timeline mark — **Correction** · Observed

The dot's class list is exhaustively `st-<status>` + `missed` + `thin` + `drag` + `dim`
(`ph-units.jsx:609-611`); the band's is `dim` + `sel` + `dragging` (`:589`). Neither
carries "personally modified" or "personally moved".

CLAUDE.md §2 makes three-tier differentiation a product contract ("respect it
everywhere"), and the shipped unit workspace already honours it
(`unit-tabs/LessonsTab.tsx:44` renders `<ForkCues lesson={l}/>`). So on the one surface
showing a teacher their whole year at once, they cannot tell which lessons are their own
forks. **The handoff is the weaker source here; the project contract outranks it.**

Note the collision risk: `border-style:dashed` is already taken by "needs work"
(`ph-units.css:61`) — pick a different channel (e.g. a ring).

### B2 · The timeline answers "where am I" but not "what do I teach next" — **Enhancement** · Observed (code) / Inferred (need)

The lane subtitle is `'Now: ' + cur.name` (`ph-units.jsx:572`) — the current **unit**,
never the next **lesson**, its date, or whether it is ready to teach. The band's only
readout is `ready/total` at `font-size:10px;opacity:.75` (`ph-units.jsx:595`,
`ph-units.css:51`).

CLAUDE.md §1 states the core job as "What are we teaching this week, and where am I in the
plan?" — the second half is served, the first is not. The primitive is already shipped:
`UnitExplorer.tsx:352-353` resolves "the first not-yet-taught lesson, else the first".

### B3 · Pacing is computed and then trapped inside a unit — **Enhancement** · Observed

`plan_workbench/pw-data.js:201-205` computes `remaining / thin / ready / total / end /
target / slack / budget`; the shipped equivalent exists (`lib/unit-insights.ts`,
`unitPace` consumed at `unit-tabs/OverviewTab.tsx:109`). On the landing, slack appears only
as a 2px tick on the band (`ph-units.css:52-53`) with no number anywhere. A teacher
scanning the year cannot see "Math is four days behind". A per-lane pace chip needs no new
data.

### B4 · Standards coverage is absent from the year view — **Enhancement** · Observed (data exists) / Inferred (value)

The app carries the standards catalog, `Lesson.standardIds` (`lib/types.ts:362-367`),
`units.standards uuid[]` (`20260728120000_track_b_workspace_fields.sql:133`), and a
standards-spread computation (`lib/unit-insights.ts:5`). The timeline surfaces none of it.

CLAUDE.md §1 names a CCSS standards doc as one of the five fragmented surfaces this product
consolidates — a year-level "which standards are still untaught" readout is the strongest
candidate for a genuinely missing data point on this surface, and needs **no new storage**.

### B5 · Empty / loading / error on the timeline: absent in the handoff BY CONSTRUCTION — **Correction** · Observed

`Timeline` derives its lanes from `[...new Set(state.units.map(u => u.sid))]`
(`ph-units.jsx:323`, mapped `:560`) and has **no loading and no error branch anywhere** —
the prototype's data is a synchronous `PW.build()`.

Copy that faithfully and an unplanned year, a still-hydrating store, and a failed fetch all
render an identical empty grid. The shipped app already has the honest pattern in the same
folder tree: `usePlannerDataState` + `PlannerEmpty` (`components/hub-v2/browse/LessonBrowse.tsx:26,82`;
`components/hub-v2/browse/CatchUpBrowse.tsx:24,67-75`).

**This is the one improvement to treat as a build blocker rather than polish.**

### B6 · No non-pointer path to move anything — **Correction** · Observed

Every authoring gesture is pointer-only: `onPointerDown={tickDrag}` (`ph-units.jsx:614`,
handler `:358-374`), band re-pace (`:432-450`), edge resize (`:453-463`), paint-new-unit
(`:377-406`), paint-new-subject (`:415-429`); the dot sets `touch-action:none`
(`ph-units.css:57`).

CLAUDE.md §4 requires full keyboard navigation. Needs a keyboard equivalent (arrow-key
nudge on a focused dot, or a "Move to date…" row-menu item) designed **into** the timeline
wave, not retrofitted.

### B7 · Unlabeled interactive elements at default zoom — **Correction** · Observed

The lesson-dot `<button>` renders its title only when `colw >= 80` (`ph-units.jsx:616`) and
carries no `aria-label` or `title`. Default `colw` is `34` (`:304`) — so at the default
zoom every lesson dot is an unnamed button. (Bands are fine: `:591` sets a rich `title`.)

### B8 · Touch targets below the contract — **Correction** · Observed

`.ph-tick{width:14px;height:14px}` (`ph-units.css:56`), and the zoom slider permits
`min="16"` px day columns (`ph-units.jsx:496`). CLAUDE.md §4 requires ≥44px on phone and
tablet.

Positive, worth preserving: the lane label **is** pinned
(`ph-units.css:41` `position:sticky;left:0`, narrowing 190px→130px at the small breakpoint
`:328`), so subject identity survives the horizontal scroll.

### B9 · The legend encodes by colour alone — **Correction** · Observed

All five legend swatches are 9px rounded squares differing only in `background`
(`ph-units.css:14-15`). The dots themselves *do* carry shape channels — filled vs hollow
(`:60`), dashed for "needs work" (`:61`) — so the legend under-describes its own encoding.
Small fix that also makes the shape channels discoverable.

### B10 · Bind the timeline's drags to the undo history that already exists — **Enhancement** · Observed

`lib/planner-store.tsx:6` wraps the document in "a 50-step undo/redo history", `:104` caps
it, `:18-19` coalesces bursts. The handoff already checkpoints each gesture
(`ph-units.jsx:363,441,457`) and toasts with Undo (`ph-app.jsx:362-366`).

This matters more than it sounds: a single dot drag re-dates **every later lesson**
(`ph-units.jsx:369` "everything after rippled"), and the count is already computed
(`:468` `PW.laterCount`). Two asks — wire the drags to the **existing** history rather than
a new one, and put the number in the toast ("moved — 7 later lessons rippled") so the
teacher can judge whether to undo.

### B11 · A "Teach next" affordance on the landing — **Experiment** · Observed (its absence)

The workspace footer carries "▶ Teach next lesson" (visible in
`screenshots/01-workspace-unit-plan.png`; the shell has a footer slot at
`components/year-v2/ExplorerShell.tsx:99,502`); the landing timeline has no equivalent. A
per-lane next-lesson chip would close the loop from B2 — but it competes for the lane
label's 190px and has not been seen rendered. Prototype before committing.

### B12 · Do holidays affect the pacing maths, or only the column tint? — **Experiment** · Unverified

The handoff paints holiday columns (`ph-units.jsx:554`, `.ph-holcol`) but pacing counts
slots (`pw-data.js:201-205`), so a holiday-heavy stretch may not move "days remaining". The
shipped side has `lib/use-holidays.ts` and `buildSchoolDays` (`lib/year-calendar.ts:90`).
**Not traced** whether shipped pacing excludes non-school days. Worth one targeted check
before the timeline wave fixes its slot vocabulary — getting it wrong makes every pace
estimate quietly optimistic for the Qatar school's Ramadan-timetable case.

## C. DATA-MODEL GAPS

### C1 · Verdict on the two questions that gate the build

**Q: Can the current schema express per-lesson "needs work" / "missed" / "target" dots?**

- **"needs work" and "missed" — YES, no migration.** They are **derived** in the design,
  not stored: `ph-more.jsx:16` `isMissed = slot < TODAY && comp(l) <= 2 && !cuHandled`, and
  `pw-data.js:46` `comp` counts filled content sections. The shipped app already has both
  equivalents: `lib/unit-workspace-derive.ts:138+` (planning-completeness gaps) and
  `lib/unit-insights.ts` (readiness). `LessonStatus` being narrower
  (`lib/types.ts:185-190`: `not_done | done | carried | skipped | partial`) is **not** a
  blocker — the design's five dot states are not five status values. **Do not widen the
  status enum.** **Observed.**
- **"target" — NO. Migration required.** `ph-units.jsx:598` renders `u.target` as a marker
  on the band. `units.target_slot` was **adjudicated OUT** of the 7.28 migration
  (`20260728120000_track_b_workspace_fields.sql:333-335`). No column, no type field.
  **Observed.**

**Q: Do units have start/end dates?**

- **Partially — no migration for week granularity.** `units.start_week` / `end_week`
  **exist** (`supabase/migrations/20260518102823_initial_schema.sql:351-352`) and are
  selected (`lib/planner/supabase-source.ts:615`). But the mapper collapses them to a
  display string `weeks: "Wk 9–14"` (`:979-981`) and the `Unit` type
  (`lib/types.ts:55-97`) exposes no numbers. Week-granularity bands need only a type
  widening + mapper change (**S**). **Observed.**
- **Day-granularity geometry and drag-resize — migration required, and a design decision
  first.** `units.position` / `anchor_slot` / `target_slot` and `lessons.pad` / `stack` are
  DEFERRED (`20260728120000…sql:36-42`, `:333-335`), with the note warning that porting
  them now "would run two scheduling vocabularies in parallel". **Observed.**
